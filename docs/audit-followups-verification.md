## Границы применения

Начальная миграция требует новой пустой БД. Существующие рабочие БД и тома
не сбрасывались; `stamp` не использовался. Перенос прежних данных требует
отдельного согласованного плана. Downgrade проверялся только на созданной
для этого тестовой БД.

Изменения основного рабочего каталога (`.gitignore` и удаление `docs/plan.md`)
не включаются в этот PR. Обновление PR не означает слияние в `main`.

Истории веток объединяются отдельным merge-коммитом со стратегией `ours`:
его дерево сохраняет проверенную реализацию `feature/audit-followups` и
уточнения документации, а второй родитель сохраняет всю историю исходного
PR #30. Поскольку исходный head PR становится предком нового head,
ветка PR обновляется обычным fast-forward push без переписывания истории.
