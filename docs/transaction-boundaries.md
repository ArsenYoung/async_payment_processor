# Границы транзакций

## Обработка платежа

Короткая транзакция читает платеж с row lock и закрепляет processing lease на 60 секунд за уникальным UUID владельца. Конкурентный обработчик повторяет короткое чтение через 50 мс, освобождая соединение между проверками. Завершенный платеж возвращается без gateway-вызова.

Gateway вызывается после commit захвата, без открытой DB-транзакции. Вызов ограничен 30 секундами. Ключ идемпотентности — UUID платежа: повторный вызов, включая восстановление после падения процесса или неясного результата commit, обязан возвращать результат той же операции без повторного списания. Любая новая реализация gateway должна обеспечивать этот контракт на стороне провайдера.

Симулятор вычисляет исход по SHA-256 UUID и настроенному success rate, поэтому результат сохраняется между экземплярами и перезапусками при одинаковой конфигурации. Случайная задержка сохраняется. Вызов симулятора без ключа оставлен для самостоятельного тестирования распределения исходов.

Отдельная транзакция проверяет токен и срок lease, сохраняет доменный результат и освобождает lease. Проверка берет row lock до commit: устаревший владелец не может перезаписать результат нового обработчика. При исключении или отмене выполняется условное освобождение только своего токена. Если БД недоступна или процесс завершился, lease становится доступен после истечения срока. Для сроков используется время PostgreSQL.
