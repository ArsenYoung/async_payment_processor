# План улучшений после аудита

Основание: сопоставление реализации с `docs/task.md`, проверка архитектуры,
транзакций, Outbox, retry/DLQ, webhook и конфигурации окружения.

## Правила выполнения

- Одна задача ниже — один законченный логический коммит.
- Код, необходимые тесты и документация конкретной задачи входят в тот же коммит.
- Перед реализацией каждой задачи согласовать точные изменения и файлы согласно
  рабочим договорённостям. Этот документ не разрешает автоматически выполнять задачи.
- Не смешивать задачи с общим форматированием и несвязанным рефакторингом.
- Названия новых файлов ниже являются предлагаемыми; уточнить их перед реализацией.
- После выполнения отмечать задачу и записывать фактические результаты проверки.
- Для каждого коммита выполнять `git diff --check` и профильные проверки ниже.
  Для Python дополнительно выполнять Ruff и mypy; перед сдачей блока — полный
  pytest на изолированных PostgreSQL и RabbitMQ.
- Для изменений схемы проверять upgrade, downgrade и `alembic check`.
- P1 — соответствие буквальному ТЗ; P2 — корректность и подтверждение работы;
  P3 — сопровождаемость; эксплуатационные задачи не являются пропущенными
  требованиями тестового задания.

### 14. Ограничить ожидание занятого lease

- [x] Выполнено.
- **Приоритет:** эксплуатационный.
- **Коммит:** `perf(processing): add bounded backoff for lease contention`

  явно повторяемую ошибку в существующую retry-политику. Сохранить проверку
  результата после освобождения lease и защиту от устаревшего владельца.

  `src/payment_processor/application/errors.py`,

  `tests/test_payment_lease_fencing.py`, `tests/test_payment_processing.py`,
  `tests/test_webhook_delivery_state.py`, `tests/test_processing_errors.py`,

  фиксированного опроса при сопоставимом ожидании; завершённая чужая работа
  переиспользуется; истёкший lease можно захватить; отмена освобождает только
  свой токен. Проверить маршрутизацию ошибки ожидания в retry.
